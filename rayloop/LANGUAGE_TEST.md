# 中文可用性:受控实验结果

## 实验设计

同一张盲测合成图(CS2 真实截图 vs 本项目画面,标签抹除、左右随机),
派两个 critic subagent,**唯一变量是指令语言**。两者都被要求先写判断、
再开答案 key,并在最后用统一格式报告 VERDICT / MATCHED / GAP / CONFIDENCE。

Ground truth: A = CS2 真游戏,B = 本项目。

## 结果

| | 英文 critic | 中文 critic |
|---|---|---|
| VERDICT | A | A |
| MATCHED | **命中** | **命中** |
| CONFIDENCE | 5(一眼) | 5(一眼) |
| 最大 gap | 「完全没有第一人称手」 | 「完全没有第一人称手臂」 |
| 输出格式合规 | 是 | 是 |
| 严苛度 | 无恭维 | 无恭维 |
| 额外发现 | — | HUD 色差、大气透视缺失 |

**结论:核心机制在中文下完全奏效。** 盲测、抹标签、二选一、拒绝恭维、
结构化输出——全部正常工作。中文 critic 反而列出了更长的优先级清单。

## 但两组都犯了同一个错,而且是同一种错

两者都把最大 gap 报成「完全没有手/手臂」。**实测:手在画面内**
(hands-only bbox y 起点 629,在 1080 高的画面里;`check_hands.mjs` 27 项断言全过)。

它们看到的是真实现象——手太暗、细节太少,被读成了枪身的一部分。
但两者都把「我没认出来」表述成了「它不存在」,并据此给出了错误的成因
(中文组进一步推断「武器直接挂在相机上」,这也不对)。

中文组还把 JPEG 压缩伪影读成了后处理色差,推断「HUD 在后处理管线内部合成」。
实测 HUD 是 DOM 覆盖层,根本不经过管线。

**这正好是 SKILL.md 里「不要盲信 critic」那一节的实例,而且它与语言无关。**
critic 对*现象*的观察两种语言下都准;对*成因*的解释两种语言下都可能错。

## 需要注意的语言相关问题

1. **触发词是英文的**(已修)。原 description 只列了 "gauntlet loop"、
   "gauntlet this" 等。中文用户说「用擂台循环做这个」「帮我写个盲测循环提示词」
   都不会命中。已在 description 中补入中文触发语。

2. **bar 的可获取性有地域性。** 「CS2 的 Dust II」全球可查;「某中文产品的
   落地页」可能需要登录、或对抓取不友好。设 bar 时要确认 critic 真能拿到,
   否则它会凭想象比较——这是这套东西最常见的失效模式。

3. **产物语言 ≠ 指令语言。** 这次全程用户说中文,而我给 agent 的指令、
   代码注释、agent 之间的通信全是英文。这是对的:代码注释是写给未来读代码的人,
   不是写给这轮对话的。但如果**产物本身**是中文(中文文案、中文报告),
   那 bar 也必须是中文的——拿英文范文当中文写作的标杆没有意义。

4. **`/loop` 和 `ultracode` 是英文关键字**,与对话语言无关,照写即可。
